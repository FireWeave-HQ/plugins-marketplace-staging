# Cleanup (measured-dead flag retirement)

The **only** lifecycle/retirement mechanism (the autonomous stability→deprecation
reconciliation is dropped). Deprecation is gated on **measured deadness**, never
an asserted status: a flag is retirable only when it is at **100%** AND has
**zero recent off-branch evaluations**. Cleanup proposes — it never auto-deletes.

## Step 0 — Auth + repo-bind precondition (fail closed, allowlist)

Run `mcp_rollout-server_ensure_auth` with
`{ cwd: <absolute open-workspace root> }` (required when known — MCP process
cwd is often not the repo). `ok: false` → `fw login` and PARK.
Continue **ONLY** when `repo_binding.bound === true` **and**
`repo_binding.orgMatch !== false`. Missing / undefined `repo_binding` → PARK
as unbound. On `orgMatch: false`: switch profile (`fw profile use`) or
`select_project` with `{ cwd }` if the bind is stale — do not blindly rebind.
**Do not write FireWeave files while unbound.** A profile alone does NOT mean
this repo is bound to a project.

## Steps

| Step                                                               | Action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1 — Find candidates**                                            | Run `mcp_rollout-server_find_cleanup_candidates`. It resolves the **shipped set** through the FireWeave seam (fw-server → `.fireweave/.cache/` projection → tracked file), with `retiring` tombstones already applied — **never a listing of `.fireweave/rollout-ready/`**, which in a migrated repo is empty (cleanup would find nothing and the dead flags would live forever) and in a legacy repo includes drafts nobody shipped. Supply a `measure` callback that queries PostHog in the **completed rollout's environment** (resolve via `GET /v1/rollouts/:id` → `environment`, then `get_project_capabilities` with that env for `posthogProjectId`). Without env-scoped measurement every candidate is `measurementPending`. **Read `absence` before reading `candidates`.** The result carries `source`, `shape`, `projectionUsable` and — when the shipped set could not be READ at all — `absence` + `absenceFix`. An empty `candidates` beside a set `absence` means _I could not look_, not _there is nothing to retire_: classify it before concluding anything (`not-fetched` → `fw sync`; `not-authorized` → the manifests are **withheld, not absent**; `server-unavailable` → retry). An unclassified absence must never be reported as "nothing to retire". |
| **2 — Reconcile before removal**                                   | Run `mcp_rollout-server_reconcile` to confirm the flag's manifest entry, code anchor, and stamp are consistent before proposing removal — a measured-dead flag that still has live call-sites must drop its code branch + manifest entry + stamp together (same PR).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **3 — Propose retirement**                                         | For each confirmed measured-dead change, propose (via `a stop-and-ask user prompt`): retire the flag at the provider, remove the dead flag-off branch, **write the retirement tombstone** (Step 4), and retire the associated guardrail/adoption metrics. Apply only on explicit confirmation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **4 — Retire through the server (tombstone now, archive on ship)** | Call `mcp_rollout-server_guarded_call` `{ toolName: "retire_repo_manifest", args: { projectId, repoResourceIdentifier, branch: <this branch>, feature } }` → `POST /v1/repo-manifests/retire`. **There is no `_archive/` directory and no stamp file to move** — archival is a `status` on a server row, and change stamps are archived with the manifest in the same transaction (M2). `branch` is non-null by design. Idempotent: a second call returns `already-retiring`, which is a success, not a no-op to retry around. `404 MANIFEST_NOT_SHIPPED` means nothing shipped this feature — do **not** "fix" it by authoring or archiving something else.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **5 — The global archive lands when the cleanup itself ships**     | The tombstone shadows the shipped contract **in this branch's view only**. That is deliberate: an immediate global archive would orphan `main`'s still-present `// @fireweave-flag` anchors, blocking every gate on every other branch for a cleanup that has not merged and may never merge. The global flip happens when the cleanup change ships — `/fireweave:safe-rollout` registration naming the feature (`manifestFeature`), or `guarded_call` `{ toolName: "promote_repo_manifest", args: { projectId, repoResourceIdentifier, branch, feature } }` on the same branch. Landing returns `outcome: 'retired'` with `archivedStampIds`. **Do not chase the archive by hand** and do not reach for the `/archive` break-glass to shortcut it — that route is immediate and global, and it is exactly what this two-step exists to avoid.                                                                                                                                                                                                                                                                                                                                                                                                                                    |

Every clarification uses `a stop-and-ask user prompt`.

## Do not

- Delete or move a manifest file, or create an `_archive/` directory — neither has a successor; retirement is a server transition.
- Delete a change-stamp file. Stamps live in `change_stamps` and are archived with the manifest.
- Remove a `FW_STAMPS` line as a substitute for retirement — the stamp line is git-visible bookkeeping, not the contract.
- Archive globally (`/archive`, `branch: null`) as a shortcut for `/retire` → ship.
- Propose retirement on `measurementPending` — deadness is measured, never asserted.
