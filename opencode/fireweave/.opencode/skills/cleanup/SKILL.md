# Cleanup (measured-dead control-point retirement)

The **only** lifecycle/retirement mechanism (the autonomous stability→deprecation
reconciliation is dropped). Deprecation is gated on **measured deadness**, never
an asserted status: a control point is retirable only when it is at **100%** AND has
**zero recent off-branch evaluations**. Cleanup proposes — it never auto-deletes.

## Running FireWeave's tools (`fw tool`)

This skill runs FireWeave's tools through the `fw` CLI in your shell, as `fw tool <name>`. There is no FireWeave MCP server.

- **Which `fw`.** Run `command -v fw`; when it prints nothing, use `~/.fireweave/bin/fw` (`fw.exe` on Windows) if that file exists. Then run `fw tool list --json`: its `binary.realpath` is the `fw` that answered. When that is not the installed FireWeave binary (`~/.fireweave/bin/fw`, or wherever the user installed it), stop and say which `fw` is first on `PATH`.
- **Input.** Write the tool's input as one JSON object to `.fireweave/tmp/<name>.json` with your file-editing tool, then run `fw tool <name> --input-file .fireweave/tmp/<name>.json` from the repository root. A tool that needs no input runs as `fw tool <name>`. Leave `cwd` out: `fw tool` takes it from the shell's directory, clamped to the repository. `.fireweave/.gitignore` ignores `tmp/`; add that line when it is missing.
- **Output.** One JSON envelope, `{ "status", "exitCode", "reason"?, "result"? }`; `result` is the tool's own answer. Exit `0` ok · `1` refused · `2` bad input · `3` auth (`fw login`) · `4` upgrade (`fw self-update`) · `5` unavailable (retry later). A refusal never exits 0.
- **Plain commands.** One `fw …` command per shell call, and each `fw tool` command on its own (FireWeave's hook refuses one joined to anything else); other commands may form a plain `&&` chain: no redirection, no heredocs, no `$(…)`, no `VAR=` prefixes, no globs, and never `fw api`. Hosts pre-approve plain `fw tool`, `fw status` and `fw sync` commands; `fw manifest …`, `fw login` and `fw select-project` ask the user first.

## Step 0 — `fw`, auth and the repo binding (fail closed, allowlist)

### Step 0.0 — `fw` reaches FireWeave from this shell (fail closed)

Run `fw tool list --json`, then `fw tool ensure-auth`, from this shell, not from what an earlier session saw. **PARK, writing nothing,** and say which case it is:

| What happened                                                                             | Tell the user                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fw` is not found (see **Which `fw`**)                                                    | install the `fw` CLI (`docs/install.md`), then run `fw plugins install`: it installs FireWeave's skills and the allow rule that lets this agent run `fw`. Then run this skill again                                   |
| `fw tool list --json` lacks a tool this skill's **Tool manifest** names                   | this `fw` is older than the skill: `fw self-update`, then `fw plugins install`                                                                                                                                        |
| `fw tool ensure-auth` exits `5`, or its `result.create_permission.cause` is `unreachable` | this shell cannot reach FireWeave: it is sandboxed or offline. `fw plugins install` writes this agent's allow rule for `fw`, which lets `fw` reach FireWeave from a sandboxed shell; or run where the network is open |
| `fw tool ensure-auth` exits `3`                                                           | `fw login`, then run this skill again                                                                                                                                                                                 |

### Step 0.1 — the repo binding

Read `result.repo_binding` from the same `fw tool ensure-auth` envelope.
Continue **ONLY** when `repo_binding.bound === true` **and**
`repo_binding.orgMatch !== false`. Missing / undefined `repo_binding` → PARK
as unbound. On `orgMatch: false`: switch profile (`fw profile use`) or, when
the bind is stale, `fw select-project` (it asks first) — do not blindly rebind.
**Do not write FireWeave files while unbound.** A profile alone does NOT mean
this repo is bound to a project.

## Steps

| Step                                                                | Action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **1 — Find candidates**                                             | Run `fw tool find-cleanup-candidates`. It resolves the **shipped set** through the FireWeave seam (fw-server → `.fireweave/.cache/` projection → tracked file), with `retiring` tombstones already applied — **never a listing of `.fireweave/rollout-ready/`**, which in a migrated repo is empty (cleanup would find nothing and the dead control points would live forever) and in a legacy repo includes drafts nobody shipped. It has no live measurement source of its own: a candidate is measured in its **completed rollout's environment** (the rollout's page in FireWeave names it; `fw tool get-project-capabilities` with `{ "projectId": "<projectId>", "environment": "<env>" }` reads that environment's bindings). Without env-scoped measurement every candidate is `measurementPending`. **Read `absence` before reading `candidates`.** The result carries `source`, `shape`, `projectionUsable` and — when the shipped set could not be READ at all — `absence` + `absenceFix`. An empty `candidates` beside a set `absence` means _I could not look_, not _there is nothing to retire_: classify it before concluding anything (`not-fetched` → `fw sync`; `not-authorized` → the manifests are **withheld, not absent**; `server-unavailable` → retry). An unclassified absence must never be reported as "nothing to retire". |
| **2 — Reconcile before removal**                                    | Run `fw tool reconcile` to confirm the control point's manifest entry, code anchor, and stamp are consistent before proposing removal — a measured-dead control point that still has live call-sites must drop its code branch + manifest entry + stamp together (same PR).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **3 — Propose retirement**                                          | For each confirmed measured-dead change, propose (via `the `question` tool`): retire the control point at the provider, remove the dead off branch, **write the retirement tombstone** (Step 4), and retire the associated guardrail/adoption metrics. Apply only on explicit confirmation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **4 — Retire through the server (tombstone now, archive on merge)** | Run `fw manifest retire --feature <feature> --branch <this branch> --json` → `POST /v1/repo-manifests/retire`. It is a typed command, not an `fw tool`, so the host asks the user before it runs. **There is no `_archive/` directory and no stamp file to move** — archival is a `status` on a server row, and change stamps are archived with the manifest in the same transaction (M2). `--branch` is required in effect: the tombstone is branch-scoped by design. Idempotent: a second call returns `already-retiring`, which is a success, not a no-op to retry around. `404 MANIFEST_NOT_SHIPPED` means nothing shipped this feature — do **not** "fix" it by authoring or archiving something else.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **5 — The merge into each environment branch lands the tombstone**  | The tombstone shadows the shipped contract **in this branch's view only**. That is deliberate: an immediate global archive would orphan `main`'s still-present `// @fireweave-controlpoint` anchors, blocking every gate on every other branch for a cleanup that has not merged and may never merge. Open the cleanup's pull request like any change. **Merging it into each environment branch lands the tombstone there (F2)**: with one shared branch that merge archives the shipped manifest and its stamps; with a branch per environment, each merge records its environments and the last one archives. There is nothing to call — no registration naming the feature and no promote. Landing archives with `archivedStampIds`. **Do not chase the archive by hand** and do not reach for `fw manifest archive` (the break-glass) to shortcut it — that route is immediate and global, and it is exactly what this two-step exists to avoid.                                                                                                                                                                                                                                                                                                                                                                                                  |

Every clarification uses `the `question` tool`.

## Do not

- Delete or move a manifest file, or create an `_archive/` directory — neither has a successor; retirement is a server transition.
- Delete a change-stamp file. Stamps live in `change_stamps` and are archived with the manifest.
- Remove a `FW_STAMPS` line as a substitute for retirement — the stamp line is git-visible bookkeeping, not the contract.
- Archive globally (`fw manifest archive`, `branch: null`) as a shortcut for retire → merge.
- Propose retirement on `measurementPending` — deadness is measured, never asserted.
